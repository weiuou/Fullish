# 路线图

## 当前能力

已具备单机镜像发布与回滚、QQ 官方适配器、CPA 模型调用、按群短期上下文和开发者私聊菜单。普通消息提供上下文，@ 或名称触发回复；支持多模态输入、媒体生成与表达后处理。

工具能力包括搜索、沙箱、钱包、动态 MCP 及只读 CPA 订阅额度查询。各功能按现有群策略与工具授权控制，配置说明见 [QQ 接入](qq-setup.md)、[动态 MCP](mcp.md) 和 [CPA 用量](cpa-usage.md)。

消息主链已按 [重构设计](https://github.com/weiuou/Fullish/issues/39) 分离上下文、回复执行、模型提供方、权限和管理模块；聊天与部署简报共用群协调和投递服务。包根仅保留启动、装配和公共配置；QQ、策略、MCP、沙箱、钱包与 CPA 实现按职责归入各自包，图片格式与 GIF 解析位于 `collection/parsers/image`。公共投递结果仍保存在进程内；Dim 单任务另有最小持久运行及投递状态登记，不提供可重放内容或 Outbox 恢复。

## 优先开发：Dim agent 与 visualize 插件

以下为 2026-11-12 修订的开发方向。旧版已完成单群受控验收；新绘图由 Dim 插件直接执行，正在验证与切换，不能沿用旧版上线结论。详细职责、接口、验收与回退见 [开发路径](agent-runtime-plan.md)，当前实现及分层证据见 [接入与验证](agent-runtime.md)。

1. 固定 Dim 版本，核验 ACP 后选择满足工具白名单要求的原生 App Server 协议，验证图片产物回传和取消/清理合同。
2. 通过现有 `ReplyModel` 接入可选 Dim 后端，首版每任务独立会话，沿用 Fullish 的群上下文、队列、权限和发送确认；增加最小持久运行登记，抑制重启后的重复执行。
3. 建立按任务授权的绘图票据与 PNG 产物桥接；验证 Dim companion 内的直接中文绘图。
4. 交付 visualize 插件，跑通“请求画图 → 渲染 → 看图修正 → QQ 确认”的完整链路，再进入单群试运行。
5. 逐步接入其他获授权工具；持续会话的增量上下文与投递回执另行实现。

首版输出 PNG，HTML/SVG/Mermaid 是绘图源码；网页托管、跨轮产物编辑和后台 agent 任务属于后续范围。长期会话不是首次接入的前置条件。

## 独立保留：一次性提醒闭环

以下为已确定的设计范围，尚未实现，可以独立于 agent 接入开发。固定文字提醒不调用 Dim；未来后台 agent 任务的结果通知依赖这里的持久投递与显式授权：

1. 在已有公共发送服务上增加提醒的显式通知授权和持久化投递记录。
2. 使用 SQLite 保存一次性文字提醒及执行、投递状态。
3. 增加简单到期扫描与启动恢复，处理有效期、撤权和结果不明。
4. 扩展已绑定开发者的私聊菜单，支持添加、查看、取消提醒和查询结果。

用少量完整链路场景验证正常到期、重启恢复、取消或撤权，以及发送结果不明。关联 trace 结合最终状态断言，模拟回放与真实集成证据分别报告。

架构边界和验收方式见 [主动消息与触发器架构草案](proactive-messaging.md)。

## 后续按需扩展

- 周期提醒、自然语言创建提醒、CPA 阈值告警和外部事件。
- 后台任务执行身份、受限 MCP 委托与更复杂的调度策略。
- 自主参与群聊、话题时效、人格与发言质量评测。
- 带来源和群作用域的长期记忆；存储扩容与多实例按实际需要决定。

当前不将通用规则引擎、事件总线、持久化媒体提醒或消息中间件纳入最小闭环。
