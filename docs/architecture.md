# 架构与部署决策

## 当前边界

当前使用 NoneBot2 + FastAPI，通过 HTTPX 调用 CPA，通过 QQ 官方适配器维持向外的 WebSocket 连接。支持按群隔离的短期上下文（文本、表情和图片占位）、@ / 名称触发回复，以及独立的[私聊开发者菜单](group-control.md)。私聊不进入聊天模型，绑定开发者后可动态控制各群功能。触发群回复时可把最近几分钟的图片作为多模态输入传给模型；尚未持久化聊天或长期记忆。不配置凭证时仍可运行部署骨架，健康响应为 `mode=foundation`。

消息采集与分类型解析位于独立的 `collection` 模块，输出带发送者元数据的统一记录；语音、视频和文件先保留类型、附件元数据及占位。边界、扩展方式和身份封装见 [群消息采集与解析](message-collection.md)。

消息发送位于独立的 `sending` 模块，文本、图片和语音分别通过适配器编码，统一候选支持同条图文；媒体来源可以是 URL、字节或本地文件。`generation` 提供可替换的内容生成协议，GPT Image 生图与参考图编辑复用 CPA 的连接与密钥。`media.assets` 在单轮回复内保存有上限的图片，群附件、公开图片读取与沙箱导出共享本轮 ID 和真实视觉输入；图片字节可用于编辑、沙箱导入或直接发送，跨轮不共享。聊天模型通过工具产生图片与配文，再交由统一出口发送。每条获得 QQ 确认后才记录文字与媒体占位到上下文。其他媒体内容提供方也可通过 `ReplyModel` 协议接入。详见 [表达后处理与媒体发送](message-sending.md)。

可选的 `reply.postprocess`位于初稿生成与实际投递之间，通过一次模型调用决定保留原稿、改写一条或生成有界的 `ReplyPlan`，支持 Unicode emoji 和运营者配置的真实图片、表情素材。它只读取当前用户语境、原稿和显式人设，不学习 AI 或群友历史表达习惯；QQ 原生表情目前使用可读回退文本。失败回退原稿，取消继续传播；全计划完成附件预检后，每条投递前重新检查剩余计划权限与 QQ 回复预算，每条确认后独立记录历史，部分失败停止后续投递。配置 AI 后端后该层默认开启，可通过环境变量关闭；不增加随机停顿或群友插话中断，仍沿用每群 FIFO 调度。

readiness 验证进程启动；独立 `/health/dependencies` 检查模型目录和 QQ 连接，避免外部平台短暂故障导致应用反复回滚。同机 CPA 通过 Unix socket 转发连接，继续只监听宿主机回环端口。配置和实际聊天策略见 [接入指南](qq-setup.md)。

采用单仓库、模块化单体。当前一台腾讯云服务器运行一个 Fullish 实例，已有发布、群聊与工具能力；聊天回复和部署简报已共用群协调与发送服务，后续完善可恢复提醒。

## 运行与发布分离

GitHub 托管运行器处理代码检查、测试和镜像构建，镜像存入 GHCR 或配置的仓库。受信任的 `main` 工作流通过受限 SSH（默认）或腾讯云自动化助手 TAT，由服务器执行预先安装的部署脚本。

此方案适合当前的单机 Ubuntu / Debian 环境：服务器保留运行配置和部署状态，GitHub 保留代码、检查结果与构建记录，镜像 digest 将一次部署精确对应到一次构建。服务器无需拉取源码或安装开发依赖。

| 信息 | 保存位置 |
| --- | --- |
| 源代码、工作流、锁文件、配置模板 | GitHub 仓库 |
| 构建镜像、提交号、digest | 镜像仓库与 Actions 运行记录 |
| SSH 主机地址、端口 | GitHub `production` 环境变量 |
| 专用 SSH 私钥、已验证的主机公钥 | GitHub `production` 环境 Secrets |
| GHCR 拉取凭证 | 每次工作流的短期 token，经 SSH stdin 传递，服务器 `/run` 临时保存 |
| TAT 命令 ID、实例 ID、地域 | GitHub `production` 环境变量 |
| 调用 TAT 的专用 CAM 凭证 | GitHub `production` 环境 Secrets |
| QQ 应用密钥 | GitHub `production` Secrets，SSH 部署时同步至服务器 `runtime.env` |
| CPA 模型密钥 | 服务器 `/opt/fullish/runtime.env`，不经 GitHub 传递 |
| 已部署与上一个成功镜像 | 服务器部署状态文件 |

生产服务器不运行可执行外部 PR 的 GitHub runner。SSH 使用仅允许指定仓库部署操作的专用身份和固定主机公钥；TAT 则调用保存的命令，不需要为 GitHub Actions 放开服务器 SSH 入站。两种部署凭证均存入受保护的 GitHub `production` 环境。

## 发布的一致性

部署输入使用 `仓库路径@sha256:摘要`，而非可能被覆盖的标签。脚本先获取镜像，再替换容器并等待健康检查；成功后记录版本，失败时尝试恢复上一镜像并将本次部署标记为失败。手动回滚优先使用缓存的上一成功镜像，即使工作流的拉取凭证已经过期也能恢复。

GitHub 部署并发控制与服务器进程锁共同限制并行更新。Compose 保持单个机器人实例，避免新旧实例同时发言。单机替换可能有短暂停机，当前不承诺无中断部署。

容器以非 root 用户运行，健康端口只绑定服务器回环地址，配置与应用镜像分开，日志使用轮转策略。需要公网 QQ Webhook 时，再按适配器要求配置域名、HTTPS 和入口转发；基础阶段不暴露健康服务到公网。

## 模块职责与依赖

网页工具把每次返回给模型的搜索结果和网页正文写入独立的私有 SQLite 记录，通过消息 `trace_id` 和调用 ID 与运行日志关联。Compose 使用持久卷保留记录，按数量和期限清理；写入失败会告警，不中断聊天。记录范围、脱敏及查询方式见 [工具说明](tools.md#回查搜索与网页结果)。

可选基础工具使用独立的有界调用层。DeepSeek 提供搜索和网页读取；同机沙箱由独立用户的 Rootless Docker / gVisor 执行，经认证 Unix socket 接受受限请求，按群复用常驻环境。启用与权限边界见 [基础工具与沙箱](tools.md)。

当前边界按 [重构设计 Issue #39](https://github.com/weiuou/Fullish/issues/39) 实现：

| 模块 | 当前职责 |
| --- | --- |
| `platforms/qq` | NoneBot 事件路由、群消息接入与开发者私聊传输 |
| `collection` | 分类型消息解析、图片格式与 GIF 内容解析，输出平台无关记录 |
| `conversation` | 有界上下文、去重、裁剪、快照与确认后的历史 |
| `reply` | 触发判断、聊天编排、模型与工具循环、多模态输入、表达后处理、失败提示 |
| `providers` | 模型协议、HTTP 传输、结构化响应、主备模型回退与有界单次请求 |
| `tools` / `generation` | 受限工具执行与媒体候选生成，不发送 QQ 消息 |
| `scheduling` | 每群 FIFO、背压、冷却、全局生成名额与停机排空 |
| `sending` | 公共投递服务、整计划预检、逐条复查、结果；QQ 编码与 API 调用位于适配实现 |
| `policies` | 群功能策略存储与统一访问决策 |
| `media` | 本轮媒体资产的 ID、去重、容量与生命周期管理 |
| `mcp` | 通用 server 注册、发现、授权路由与有界运行 |
| `integrations/cpa` | CPA 用量查询与只读 MCP server |
| `sandbox` | 独立 broker、worker、文件交换与部署检查 |
| `wallet` | 钱包签名、支付状态、专用 MCP client/server 与部署检查 |
| `management` | 开发者身份、存储、群设置、MCP 命令与认证后的命令分发 |
| `notifications` | 部署历史与摘要内容生成 |
| `app.py` | 对象装配、共享队列和投递服务、资源生命周期 |

`conversation.store` 不依赖具体模型或开发者管理服务；`reply` 接收上下文、授权和执行依赖；`providers` 不执行工具。投递服务接收平台无关的请求与传输协议，QQ `Bot`、事件对象、回复序号和平台错误留在 `sending.qq`。投递前及平台能力查询后复查本地授权，每条发送确认后才调用历史记录接口。确认消息带来源，部署通知在模型输入中明确标注。

应用、运维检查与测试均直接使用各模块的实际接口，旧模型构造类、会话兼容类、队列转发模块和表达处理转发模块已删除，不保留导入别名或动态属性转发。`management.__main__` 提供开发者运维 CLI；QQ 入口接收显式装配的 `ChatHandler` 与共享队列，不自行创建替代服务。包根仅保留 `__init__.py`、`__main__.py`、`app.py`、`settings.py`、`errors.py`、`telemetry.py`。运维命令改用各自所属包，宿主机脚本和 Docker COPY 源路径同步迁移；数据库、策略文件与环境变量格式不变，回滚不需要数据降级。

图像内容解析位于 `collection/parsers/image`：`segments` 提取消息片段元数据，`formats` 识别图片字节格式，`gif` 解码 GIF 帧、采样时间线并生成有界预览。解析器不下载、不访问模型或管理素材 ID；群附件、网页工具图片和图片编辑复用同一内容解析器。下载、素材管理与发送编码分别留在其执行边界。

迁移部署时同步安装新版 `scripts/`；发布门禁和汇报会根据目标镜像选择当前或旧版模块入口，允许回滚到目录迁移前的镜像，不在应用包内保留旧模块。沙箱仍按原独立文件名安装，systemd、socket 与隔离权限不变。已有 CPA 内置注册的旧入口仅在读取时转换为新入口，原始数据库 JSON 与授权保持不变，详见 [CPA 用量](cpa-usage.md)。

聊天和部署简报使用同一个群队列。已在群任务内执行的发送直接调用投递服务，不再次排队；等待当前群自身的任务会被拒绝。等待通知的调用方取消时，排队任务不会稍后继续发送；已经发出的请求可能结果不明。公共投递返回逐条结果与安全原因，当前结果仍在内存中，尚无持久化 Outbox 或跨重启恢复。部署通知保留原有环境配置作为独立文字通知授权，不从聊天开关推导未来提醒权限。

同一个群由 FIFO 消费者串行处理生成、可选表达后处理、发送和确认，忙碌与冷却期间的 @ 等待处理；不同群共享四个模型生成名额。进程内队列不跨重启恢复。发送前已有群权限和单事件回复次数检查，后续可增加话题时效、跨事件群预算与会话状态检查。连接状态通过依赖接口单独观测，不作为 Docker 重建或应用回滚条件。

## 数据持久化后的变化

需要长期记忆时再引入 PostgreSQL、SQLAlchemy 和 Alembic。数据库与应用镜像有不同的恢复方式：回滚应用镜像不会恢复被修改的数据。

数据库上线前必须确定备份位置、恢复演练、保留期及兼容迁移约定。优先采用新增字段等向后兼容的迁移，让上一镜像仍可运行；删除字段等破坏性变更分阶段完成。不要把自动降级数据库作为镜像回滚的一部分。

## 扩展顺序

主动消息、定时提醒、CPA 额度告警和后续自主发言的拟议架构与分阶段验收见 [主动消息与触发器架构草案](proactive-messaging.md)。公共群协调和发送出口已实现；提醒、持久化投递与其他触发器仍是后续设计。

下一步的最小范围是在公共发送服务上增加提醒存储、持久化投递、到期执行器和开发者管理入口，见 [当前路线图](roadmap.md)。周期规则、后台 MCP 委托和自主插话后移；只有实际负载需要时才拆分队列、数据库或增加实例。当前无需引入 Kubernetes 或额外服务器。
