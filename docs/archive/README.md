# 文档归档

此目录保存历史方案与被替代的说明，仅用于考证，不代表当前行为、开发要求或部署步骤。日常开发优先阅读仓库根目录指南和现行 `docs/`；调查历史、兼容性或回归来源时，再按需读取具体归档。

## 归档约定

- 每次任务开始和交付前，核对涉及的现行文档与代码、配置及已确定范围是否一致，无需加载全部文档。
- 局部过时但整体有效的指南直接修订。已被替代、取消或不再适用的完整文档移入本目录；历史片段仅在确有考证价值时单独保存。
- 使用 `YYYY-MM-DD-topic.md` 命名，顶部记录归档日期、原因、原路径、来源提交（如有）及现行替代文档。日期表示归档时间，不是原始方案产生时间。
- 保留历史正文的原意，可以修正移动后的相对链接。移动前查找入链，移动后同时核对入链、出链和章节锚点；标题改名也需要检查锚点引用。现行指南应指向现行替代，必要的历史引用须明确标注，不留两份同时声称有效的说明。
- 现行文档不重复历史正文，归档不作为日常必读上下文；常规任务不递归读取或默认检索归档。检索示例：`rg -g '!**/archive/**' '关键词' docs`。
- 归档不豁免敏感信息保护。提交前运行 `python scripts/check_docs.py` 检查本地路径和图片；该脚本不检查章节锚点与引用语义，需另行确认目标章节存在、引用内容支持正文结论，而非仅确认文件可打开。
