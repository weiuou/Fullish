# 私聊开发者菜单

开发者可以私聊 Fullish，统一管理各群的聊天、搜索、生图、沙箱开关。保存后后续消息和工具调用读取新配置，不需要修改多份环境文件或重启。管理命令由程序直接处理，不调用模型。

## 首次绑定

服务器维护者生成一个十分钟有效、只能使用一次的绑定码：

```sh
sudo docker exec fullish-bot-1 python -m fullish.control pair
```

把输出的 `绑定开发者 …` 私聊发给机器人。成功后，该私聊的平台用户身份即成为开发者；显示名、群管理员身份和聊天正文中的身份声明不授予权限。群内发送绑定命令不能绑定。绑定码不会写入数据库或日志，数据库只保存摘要与有效期。

后续私聊发 `菜单`，即可看到操作说明。私聊菜单需要 QQ 平台能向该机器人投递 C2C 事件；不依赖 Markdown 或按钮模板权限。官方 SDK 的 [C2C 收发示例](https://github.com/tencent-connect/qqbot-agent-sdk/blob/main/examples/e2e_test.py) 展示了这类事件与发送接口。

## 常用操作

| 私聊内容 | 作用 |
| --- | --- |
| `群列表` / `群列表 2` | 分页查看已收到过消息的群和功能状态，编号固定 |
| `选择 1` | 选择编号为 1 的群，随后操作作用于该群 |
| `命名 开发群` | 设置容易辨认的备注 |
| `状态` | 查看选中群的实际开关 |
| `开启 搜索` / `关闭 搜索` | 控制搜索和网页读取 |
| `开启 生图` / `关闭 生图` | 控制图片生成和发送 |
| `开启 沙箱` / `关闭 沙箱` | 单独控制该群的沙箱执行权限 |
| `关闭 聊天` / `开启 聊天` | 停用或恢复该群；停用时所有功能均不开放 |
| `默认 开启 搜索` | 调整没有单独覆盖值的群所继承的默认设置 |
| `菜单` | 返回帮助 |

拉入新群后，先在群里 @Fullish，再从私聊群列表选择即可，无需手抄 OpenID。群名不在当前 QQ 消息事件中，因此首次显示 OpenID 前八位；可以自行备注。关闭某项功能后，排队消息、后续工具调用和发送前都会检查权限；已被外部服务接受的请求无法撤回。关闭聊天不会阻止它出现在开发者群列表里。

沙箱最多为两个群开启，默认设置不能一键为所有群开启沙箱。仍保留每群独立工作区和原有隔离、限额。配置停用群后，下一次沙箱调用会回收已停用群的临时容器，再为允许的群分配资源；被回收工作区会清空。工作区本身是临时内存文件系统，不作为持久文件存储。

全局供应商凭证仍由服务器维护者配置，菜单不会显示或修改密钥；服务尚未配置时不能通过菜单开启。管理私聊只处理固定菜单命令，普通私聊不会进入聊天模型；频道私信继续忽略。私聊命令去重并限流，每位用户每分钟至多 12 条，全局至多 60 条。

## 持久化与升级

Compose 设置 `GROUP_CONTROL_DIR=/var/lib/fullish/control`，挂载主机 `/var/lib/fullish-control`。目录所有者为机器人 UID/GID 10001，权限 `0750`；`control.sqlite3` 为 `0600`，保存开发者身份、选择的群、群备注、消息去重与最多 2000 条变更元数据，不保存私聊正文。`policy.json` 为 `0640`，只包含群功能开关，由机器人和沙箱 broker 共同读取。broker 所属 `fullish-tools` 组可读策略，但不能读取开发者数据库。

首次启用导入已有 `QQ_ALLOWED_GROUPS`、`TOOLS_ALLOWED_GROUPS` 和当前图片开关，保留现有权限。此后菜单配置优先，环境变量不再覆盖开关；未开启动态管理的旧部署继续按原来的白名单工作。策略缺失或损坏时不授予群功能；已有开发者数据库但策略丢失时拒绝启动，避免重新导入旧权限。

已有部署升级须先运行新版本 `scripts/server-setup.sh` 安装挂载，并安装新的 `sandbox_server.py`、同目录的 `group_policy.py`，在 broker 环境设置 `GROUP_POLICY_PATH=/var/lib/fullish-control/policy.json`。策略文件须先从现有权限初始化，再重启 broker；通常通过新版 `scripts/sandbox-setup.sh` 完成。正常镜像升级和回滚保留管理目录，不自动删除开发者身份或设置。

服务器侧查看已绑定身份摘要或撤销某位开发者：

```sh
sudo docker exec fullish-bot-1 python -m fullish.control developers
sudo docker exec fullish-bot-1 python -m fullish.control revoke --user-ref 身份摘要
```

重新生成绑定码会使旧码失效。不要把绑定码发到群里；任何持有码并在有效期内完成绑定的私聊用户都会获得全部群的管理权限。
